# Тест-план: photo-analysis API

## Объект тестирования
REST API сервиса анализа фотографий (`/api/v1`). Сервис принимает фото, сохраняет в S3 и PostgreSQL, ставит анализ в очередь Kafka; worker вызывает analyzer по gRPC и сохраняет результат.

## Что тестируем
- Функциональность REST API: загрузка, получение, список с фильтрами, скачивание, удаление, результат анализа, повторный анализ.
- Обработку ошибок: неверные входные данные, чужие и несуществующие ресурсы, недопустимые переходы состояний.
- Асинхронную обработку: фото проходит путь `pending → done`, результат анализа соответствует картинке.
- Соответствие ответов документации (`/openapi.yaml`).
- Состояние данных в PostgreSQL после операций.

## Что не тестируем
- Точность моделей компьютерного зрения (проверяется калибровкой в репозитории сервиса).
- Нагрузку и производительность.
- Swagger UI.

## Подход
- Уровень: API-тесты (серый ящик — API + SQL-проверки в БД).
- Инструменты: Python, pytest, requests, jsonschema, psycopg, Pillow (генерация тестовых картинок), Allure.
- Изоляция: каждый тест работает от своего пользователя (`X-User-ID`), созданные фото удаляются после теста.
- Асинхронность: ожидание результата опросом с таймаутом, без фиксированных пауз.
- Запуск: локально и в GitHub Actions на стеке в Docker Compose.
